# 細部規格 — 幣別與交易對（currency）〔範圍一〕

> 上層文件：`00_overall_spec.md`　**範圍二續篇：`01-2_currency_spec.md`**（幣別的鏈上屬性）
>
> 本檔只談**範圍一（純內部帳本，不碰鏈）**。接上測試鏈後幣別要補的鏈上屬性（在哪條鏈、合約地址、精度、確認數）全部收在 `01-2`。

## 一、需求方規格

### 1. 模組職責

定義「系統裡存在哪些幣」。幣別是整個交易所的基礎:錢包必須指定屬於哪一種幣、訂單必須指定要買哪種幣、賣哪種幣。此模組資料量小,但被其他所有模組依賴。

### 2. 幣別

幣別是系統的最小計價單位。每一種幣需要兩項資訊:

- **代碼**:辨識用的短代號,全大寫、彼此唯一,例如 USDT、BTC、ETH。
- **名稱**:給人閱讀的全名,例如 Tether、Bitcoin。

### 3. 交易對

交易對是兩種幣的買賣組合,寫作 `BASE/QUOTE`,例如 `BTC/USDT`:

- **標的幣(BASE)**:被買賣的對象,此例為 BTC。
- **計價幣(QUOTE)**:用來定價與付款的幣,此例為 USDT。
- **價格**:一顆標的幣值多少計價幣。`BTC/USDT = 30000` 表示 1 BTC = 30000 USDT。

### 4. 對外行為

- 可查詢系統中所有幣別的清單。
- 可查詢單一幣別的資料。
- 可新增幣別(得由後台管理介面手動建立,對外新增介面為選做)。

### 5. 邊界與驗收條件

- 幣別代碼全域唯一,不得重複。
- 幣別代碼統一以大寫保存;`btc` 與 `BTC` 視為同一種幣,不得因大小寫差異被當成兩種幣。
- 系統中至少存在兩種幣別(建議 USDT 與 BTC,便於後續驗證 `BTC/USDT` 市場)。
- **驗收**:能在後台看到已建立的幣別,或透過查詢清單取得所有幣別。

### 6. 進階需求(逐步加深)

核心撮合完成後,回頭強化此模組:

- **獨立交易對**:把「哪些幣可互相交易、以及各市場的交易規則(最小下單量、價格與數量精度、手續費率、是否開放交易)」集中為獨立實體。下單改為「指定交易對 + 買/賣方向」,較賣出幣/買入幣的表達更清楚,也便於集中管理各市場規則。
- **幣別精度**:不同幣的小數位數不同(如 BTC 到 8 位、USDT 到 2 位),進階時可為每種幣設定各自的精度。
- **啟用/停用**:可下架某幣別,下架後擋掉相關下單。

## 二、開發方規格

> 對應 app:`currency`　主要 model:`CurrencyModel`、`TradingPairModel`(進階)

### 1. 資料模型(現況)

`CurrencyModel`(繼承 `BaseTimeModel`,自帶 `created_at` / `updated_at`):

| 欄位 | 型別 | 說明 |
|---|---|---|
| `code` | CharField(10), unique | 幣別代碼,如 `BTC` |
| `name` | CharField(50) | 幣別名稱,如 `Bitcoin` |

範圍一此模型已足夠,基本階段不需更動。

### 2. API(基本階段)

- `GET /api/currency/` — 列出所有幣別
- `GET /api/currency/{id}/` — 查單一幣別
- `POST /api/currency/`(選做)— 新增幣別(亦可僅在 admin 後台建立)

幣別資料變動極少,初期可只用 admin 後台手動建立數筆(USDT、BTC、ETH),暫不提供 API。

### 3. 進階資料模型

#### 3.1 交易對 `TradingPairModel`

| 欄位 | 說明 |
|---|---|
| `base` | FK 到 `CurrencyModel`(標的幣) |
| `quote` | FK 到 `CurrencyModel`(計價幣) |
| `min_order_amount` | 最小下單數量 |
| `price_precision` | 價格小數位數 |
| `amount_precision` | 數量小數位數 |
| `fee_rate` | 手續費率 |
| `is_active` | 是否開放交易 |

#### 3.2 幣別精度

現況 `DecimalField` 統一使用 `decimal_places=2`。進階時改為可為每種幣設定各自的精度。

#### 3.3 啟用/停用

加入 `is_active` 欄位,下架某幣別時擋掉相關下單。

### 4. 技術約束與注意事項

- **代碼正規化**:`code` 一律以大寫保存(寫入前 `.upper()`),並維持 unique,避免大小寫差異造成重複幣別。
- **精度**:`decimal_places=2` 不足以表達 BTC(常見到小數第 8 位);範圍一暫以統一精度處理,進階階段須為各幣設定專屬精度。
- **金額運算**:一律使用 `Decimal`(`DecimalField` 已處理),不得使用 `float`,以避免二進位浮點誤差(如 `0.1 + 0.2 != 0.3`)。
